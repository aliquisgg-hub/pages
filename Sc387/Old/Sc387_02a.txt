        → 知識

      → メタ機構(入出力→知識)

<4:探索: 探索の基本的な考え方・盲目的探索法>
(OR)木探索の一般的な枠組
  begin
    S ← {root}
    loop
      p ← pick(S)
      if is_goal(p) then exit_as_success
      S ← remove(S,p) ∪ children(p)
      if empty(S) then exit_as_failure
    end loop
  end

探索手法(戦略)
  ※pick(S)の「選び方」に依存する
  盲目的探索
    縦型探索
    横型探索
  発見的探索
    最良優先探索
      A*アルゴリズム
    山登り法

縦型探索: SがLIFO
  無限木の場合，探索が停止しないことがある
  Sのサイズが木の高さ程度(比較的小さい)
  ※バックトラック

横型探索: SがFIFO
  無限木でも，ゴール節点が存在するなら
  必ず(いつかは)停止する
  Sのサイズが木の幅程度(比較的大きい)

最良優先探索:
  ヒューリスティック関数f(p)を用いて，
  節点毎に評価値を計算して最大のものを選ぶ．
  評価関数の良し悪しで全てが決まる．

A*アルゴリズム(p.32)
  f(p) = g(p)+h(p) ≦ g(p)+h~(p)

  例: 地図の塗りわけ問題
    v_i: 国
    D_i: 色
    制約条件: 隣接する国が異なる色．
              v_1 ≠ v_2 など
  一般形:
    V={v_1,…,v_n}
    D_1,…,D_n 但し v_i∈D_i
    P={P_i(v_j,…),…}
      P_iは引数の個数に比例した計算量で評価可
    全ての制約を満たすn個組を全て見つける
  他の例:
    クロスワードパズル(言及のみ)
    線画解釈問題
      条件:
        影・クラックがない
        全て3面頂点
        一般位置
      頂点ラベルが18(16)種類
    変数-値
      線分-記号 → 多項制約
      頂点-ラベル → 二項制約

その解法

  変数の逐次的例化(縦型探索)

<8:知識表現(概説): プロダクションシステム>
プロダクションシステム(PS)
(=ルールベースシステム,応用人工知能)
  ワーキングメモリ(WM)
  プロダクションメモリ(PM)
  インタプリタ
  (感覚器)
  (効果器)
[図示]

WM(=データベース,短期記憶)
  「データ」や「推論の途中経過」
  WM要素の集まり
    ルールによって追加・削除される
[例]
  項: (述語 対象1 対象2 …)
  対象: 定数シンボル or 変数シンボル
  WM要素: 項
  WM: 項の集合(リスト)
  ※積木の例
    ((on-table a) (on c a) (clear c)
     (on-table b) (clear b))

PM(=知識ベース,ルールベース,長期記憶)
  ルールの集まり
  ルール(プロダクション-,プロダクション)
    条件(Condition) → 動作(Action)
    条件 - WMに関する記述(パターン)
    動作 - WM要素の追加・削除
[例]
  ルール: (ルール名 条件部 --> 動作部)
  条件部: 項のリスト
  動作部: 項のリスト
  PM: ルールの集合(リスト)
  ※積木の例
  ((tsumu
    ((on-table *x) (clear *x) (clear *y))
    --> ((clear *x) (on *x *y)) )
   (orosu
    ((on *x *y) (clear *x))
    --> ((clear *x) (clear *y) (on-table *x)) ))

インタプリタ(=推論エンジン)
  「推論」サイクルを制御する

「推論」サイクル
  パターン照合
    PMの各ルールの左辺(条件部)をWMと照合し，
    合致するものの集合(競合集合)を得る
  競合解消
    競合集合から1つを選ぶ
  右辺実行
    選ばれたルールの右辺(動作部)を実行する
[例]
  ※積木の例

パターン照合の問題
    WM要素単位の照合
    変数の整合性
  を同時に解決すべき(結合演算)
  同じルールでも異なる照合が可能

競合解消
  競合集合から1つを選ぶ
  選び方が「解の探索」の効率に影響する
  「戦略」とよばれる

推論の方向
  前向き推論(データ駆動,ボトムアップ)
  後ろ向き推論(ゴール駆動,トップダウン)
  双方向推論
[例]
  ※積木の例

音声認識
  音声→文字列等
  種別
    認識対象(単語/音節/音素)
    孤立音声/連続音声

  手順
    境界決定(単語/音節/音素)
      パワーの変化など
    パタン認識
      音声 －(フーリエ変換)→
      スペクトル成分 －(縮約)→
      特徴パラメタ －(判別関数)→
      認識カテゴリ(音素など)
      ※スペクトル成分と標準パタン
      のマッチングもある(単語など)
        DPマッチング(時間軸上の伸縮)
    ※境界決定とパタン認識は
    密接な関係があるので，
    平行して行なうこともある
      2段DPマッチング
  困難
    連続音声の「境界決定」は難しい
    個人差が大きい
    音声「だけ」では難しい
      「制約」が必要
      (語彙的・文法的・意味的制約，
       統計的制約(マルコフ))
    子音の認識は難しい
      スペクトルは定常的な情報
      ←瞬間的・過渡的な音声
      　(子音)には適さない
